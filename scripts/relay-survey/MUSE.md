# muse への指示文

以下をそのまま muse に渡してください。

---

あなたの仕事は、anoDB（Nostr リレーを使う暗号化データベース）が使う**リレーの候補一覧**を作るための定期調査です。公開されている Nostr リレーを調べて、anoDB で安定して使えるものを判定し、結果を報告してください。

## 場所

- リポジトリ: https://github.com/sho-ritz/anodb
- 作業フォルダ: `scripts/relay-survey/`
- 判定基準と手順の正本: `scripts/relay-survey/CRITERIA.md`（**最初に必ず全部読む**。この指示文と食い違ったら CRITERIA.md に従う）

## 準備（最初の 1 回だけ）

1. リポジトリを取得し、`scripts/relay-survey/` に移動する
2. `npm install` を実行する（Node.js 18 以上）
3. `data/probes.json` があることを確認する（保持期間を測る起点。消さない）
4. 最初に `npm run weekly` を 1 回実行する

## 定期作業

| 頻度 | コマンド | 内容 |
|---|---|---|
| 毎日 1 回 | `npm run daily` | 読むだけ。つながるか・前に書いた確認用イベントが残っているかを記録し、判定し直す |
| 週 1 回 | `npm run weekly` | リレーを探し直し、書き込み試験をして判定する（30 分ほど） |

同じ日に 2 回以上実行しないでください（結果のファイルが日付ごとに上書きされます）。週 1 回の作業をした日は、毎日の作業は不要です。

## 報告

毎回の実行後、次の内容を日本語で短く報告してください。

1. `select` が表示したまとめ（`status`・`failedBy`・`selected`）
2. 合格（pass）の数と、前回の報告からの増減
3. 前回の候補（`data/pool/` の前回の日付のファイル）から外れたリレーと、その理由（`data/evaluation.json` の `reasons`）
4. 確認用イベントが消えたリレー（`daily` の出力の「lost at least one probe」の内訳）
5. 合格が 100 に届かない場合は、その旨と主な原因
6. エラーで止まった場合は、そのメッセージ

数字は出力やファイルから読み取ったものだけを書き、推測で補わないでください。

## 守ること

- 書き込みをするのは週 1 回の `check` だけ。毎日の作業では書き込まない
- リレーに拒否されたら記録するだけにする。鍵や IP を変えて再試行するなど、**回避しようとしない**
- `survey.mjs`・`CRITERIA.md`・anoDB 本体（`src/` など）を変更しない。変えたほうがよいと思ったら、提案として報告する
- `data/probes.json` を消したり書き換えたりしない
- git の commit・push・PR 作成をしない。候補の一覧を anoDB に取り込むのは人間が行う
- 調査に関係のないリレーやサービスに接続しない
