# anoDB 設計決定ログ（v0.2〜v0.4）

> 2026-11-10 の grill-me セッションで確定。方針: **既定は最も強いセキュリティ**。
> 根拠と詳細は [DESIGN.md](DESIGN.md)、ワイヤフォーマットは [../PROTOCOL.md](../PROTOCOL.md)。

| # | 論点 | 決定 |
|---|---|---|
| 1 | 共有モデル | **グループ鍵（暗号化）＋各メンバー自身の鍵で署名＋メンバー表で権限検証** |
| 2 | 変更イベントの署名者 | **端末鍵**。本人の鍵（identity）は「この端末鍵は私の代理」という委任に一度だけ署名 |
| 3 | 本人の鍵の保存（既定） | **端末のセキュアストレージで暗号化保存**。オプションで「端末に残さず復元用キーとして一度だけ渡す」(`identity: 'recovery'`) |
| 4 | Node での鍵 | **環境変数が既定**（Node は主用途ではない） |
| 5 | `.env` の中身 | `ANODB_DEVICE_KEY` と `ANODB_DELEGATION` のみ。本人の鍵は入れず、復元用キーとして表示するだけ |
| 6 | `npx @anodb/cli init` | 対話式。環境 → フレームワーク → ドライバ → appId → 鍵 → リレー（疎通確認）→ ファイル生成。ブラウザ等ではエンドユーザー端末で鍵生成、init で鍵を作るのは Node のみ |
| 7 | init の言語 | 最初に 日本語 / English を選ぶ。**対話表示だけ**に反映（コード・エラー・ドキュメントは対象外） |
| 8 | 個人データ | **メンバー1人のスペース**として統一。スキーマは全スペース共通、各行は1スペースに属する |
| 9 | 役割 | **owner(1) / admin / writer / reader**、スペース単位 |
| 10 | 権限の衝突 | 同格同士の同時削除は**両方有効**、上位ロールが優先。削除時に**端末ごとの通し番号のカットオフ**を含め、それ以降の書き込みは拒否（衝突時は小さい方） |
| 11 | 新メンバー / 鍵更新 | 新メンバーには**現在状態のスナップショットのみ**（過去の鍵は渡さない）。グループ鍵は**削除・端末失効・追加・30日ごと**に更新 |
| 12 | メタデータ | **二重封筒**（外側は使い捨て鍵で署名、中で端末鍵署名）＋**世代ごとに変わる秘密由来のタグ**が既定。`metadataProtection: 'none'` で無効化可 |
| 13 | 招待 | **npub＋鍵パッケージ**と、**承認必須・使い捨て・期限付きリンク / QR** の両方。招待された側は承諾しないと参加しない |
| 14 | 端末追加 / 全端末紛失 | **QR ペアリング**（本人の鍵はコピーしない）。グループ鍵は端末鍵宛てのみ → **全端末紛失で個人スペースは永久に失われる** |
| 15 | 署名者 | **NIP-07 / NIP-46 / NIP-55** を共通 `Signer` で。公開イベントは本人の鍵で署名（recovery モードでは署名者が必要） |
| 16 | 公開データ | スキーマで**公開テーブル**を宣言（kind 0/1/3/7/30023 プリセット）。書き込みも `insert` |
| 17 | 型安全 SQL | **Kysely** の SQL ライク API に一本化（非同期）。生 SQL の書き込みは**トリガーで捕捉**して同期。旧 table API は廃止 |
| 18 | 同期 | **NIP-77 → 時刻ベースのフォールバック → 通し番号による欠落検出 → スナップショット**の4層 |
| 19 | 古いイベント | スナップショットは自動作成。NIP-09 削除依頼は既定オフ（`pruneOldEvents: true` で有効） |
| 20 | リリース | v0.2 土台 → v0.3 共有 → v0.4 同期と公開。v0.1 互換は捨てる（protocol v2） |
| 21 | 大きなファイル（2026-11-10 追加） | **Blossom** に端末側で暗号化して保存し、参照だけを DB に。複数サーバーへミラー、ハッシュ検証、ファイルごとの使い捨て鍵で認可（アップロードした端末だけ削除可）。暗号文を拒否するサーバーを Content-Type の偽装で回避することはしない |
| 22 | 通信経路（2026-11-10 追加） | **WebRTC を主、リレーを予備**に。シグナリングは Nostr リレー（nostr-p2p、public 化）。既定は**自分の端末同士だけ**直接接続、他メンバーとは `p2p.mode: 'members'` で（IP が見えるため）。全端末が ack したときだけリレー保存を省く |
| 23 | 型と UI（2026-11-10 追加） | Kysely の結果は **boolean → true/false、json → 値**（クエリの構文木から列の型を解決。生 SQL は SQLite の値のまま）。共有・端末追加の **React 部品を同梱**（`<PairDevice />` など）。リンクと QR は `https://アプリ/#anodb=…` で、開いても**クリックなしでは承認しない**・ペアリングは必ずコード照合 |
| 24 | 行の所有権（2026-11-12 追加） | **行は作った人のもの**を既定に。行 ID に作成者の identity を埋め込み（`<pubkey>-<乱数>`）、全端末が受信時に「その行を変えられるのは作成者だけ（削除は owner / admin も可、編集は不可）」を検証。`createdBy` / `updatedBy` は署名から自動で埋まり偽装できない。共同編集の表は `shared()` で明示。**スナップショットは owner / admin（と自分の端末）からのものだけ信頼**（writer のスナップショットで他人の行を書き換えられた穴を塞ぐ）。HLC は書き手が選べるので「最初に作った人」を時刻で決める方式は採らない |
